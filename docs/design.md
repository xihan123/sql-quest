## 1. 产品定位

SQL Quest 让学习者在浏览器中读题、看数据、写 SQL，再运行查询检查结果。提示、草稿和通过记录帮助学习者继续练习。

编辑器、执行和判题由应用实现，教学内容由 JSON 描述，静态托管或 API 只负责分发内容。

- 一个根 JSON 组织课程与主题，登记各主题的章节、关卡 ID、名称和 JSON 地址。
- 每道关卡用独立 JSON 描述教学任务、提示、答案和判题用例；数据夹具同样使用 JSON。
- 当前内置图书、商品和校园选课三个主题，共用编辑器、表格、SQL 引擎、判题与记录系统。新增业务主题不添加逐主题代码。
- 静态 JSON 文件和 API 返回同一种结构；正常增加主题或关卡不修改、不重新构建前端。
- SQL 在浏览器内真实执行，API 不接收学生 SQL、草稿、查询结果或进度。

主题可以使用不同业务数据，但都属于 SQLite 只读查询练习，不扩展到其他游戏类型、数据库方言或脚本插件。

### 产品范围

提供课程目录、题目与数据预览、SQL 编辑与补全、运行判题、三层提示、参考答案、草稿、通过记录、复习标记和备份。教学流程图与 SQL 拼图由关卡按需配置；文本编辑始终保留，不要求每关都有辅助内容。

先修用于学习建议，允许跳关和重复练习。首屏按根配置顺序进入第一个开放关卡，不固定为商品主题，也不增加营销首页。根配置可以没有开放关卡，此时显示未开放状态，不把有效的空课程当作加载失败。

不提供账号、云同步、排行榜、投稿后台、站内 AI、遥测或服务端判题。内容可由静态托管、对象存储或独立服务提供，前端不绑定服务端技术。答案和判题数据会下载到浏览器，本项目不适合保密考试。

## 2. 总体架构

```text
根配置 URL
  -> 获取根 JSON
  -> 获取根中登记的关卡 JSON、夹具 JSON
  -> Schema 与跨文档校验
  -> 生成完整、只读的课程快照
       -> React 练习台
       -> IndexedDB 学习记录
       -> SQL 请求快照
            -> Web Worker
            -> JSON 夹具编译为初始化 SQL
            -> SQLite WASM 内存数据库
            -> 完整结果比较
            -> 返回反馈
```

### 技术选型

| 职责     | 方案                                     | 边界                             |
| -------- | ---------------------------------------- | -------------------------------- |
| 前端     | React + TypeScript + Vite                | 单工程静态 SPA，不使用 SSR       |
| 样式     | CSS Modules + CSS 变量                   | 不默认引入组件库                 |
| 状态     | 组件状态，按需 reducer / Context         | 不预设全局状态库                 |
| 编辑器   | CodeMirror 6                             | SQL 高亮与补全、键盘和中文输入   |
| 执行     | SQLite WASM + Web Worker                 | 单线程、内存数据库，不使用 OPFS  |
| 本地记录 | IndexedDB                                | 只保存学习状态，不保存练习数据库 |
| 内容     | JSON + JSON Schema + Ajv                 | 类型与校验器由同一 Schema 生成   |
| 网络     | Fetch + AbortController                  | GET、限时限量、可取消            |
| 工具     | npm、TypeScript strict、ESLint、Prettier | 单一锁文件，依赖按选定版本锁定   |

模块按职责分离：HTTP 层只读取文档，内容层校验并组织课程，UI 只消费内容，Worker 执行 SQL，比较器判定结果，存储层管理记录。不得在组件里复制判题逻辑，也不得让 Worker 自行获取另一份课程。

## 3. 内容模型与身份

### 3.1 层次关系

```text
课程根配置
  -> 主题 theme
      -> 章节 chapter
          -> 关卡索引 id / title / path / prerequisites
  -> 共享夹具索引 id / path

关卡文档
  -> 目标、知识、题目、可读表、模板、提示、答案
  -> 测试用例 -> 已登记的夹具
```

主题各自定义章节、顺序、先修和知识点。主题不必共享关卡数量或编号；导航、下一关、进度分母均从该主题目录计算。

### 3.2 稳定身份

稳定关卡身份为 `(courseId, themeId, lessonId)`，实际记录键为 `(courseId, themeId, lessonId, revision)`，其中 revision 是关卡版本。不使用显示名称、数组下标或内容 URL 作为身份。不同主题可使用相同关卡 ID，不同 revision 各自保存草稿和进度。

| 标识            | 用途                                                                    |
| --------------- | ----------------------------------------------------------------------- |
| `schemaVersion` | 文档结构版本，当前各类均为 1；与内容 revision、IndexedDB 数据库版本无关 |
| 根 `revision`   | 一次课程发布；清单或引用内容改变时递增                                  |
| 关卡 `revision` | 题目、数据或判题语义改变时递增                                          |
| 夹具 `id`       | 包含数据版本，例如 library-basic-v1；发布后不原地改语义                 |
| `contentToken`  | 客户端生成的本次加载标记，只隔离异步快照，不持久化                      |

修改标题或分发地址不改变学习身份。根 revision 更新不自动使所有关卡失效；同一关卡身份下按关卡 revision 分别保存学习状态，具体规则见第 7 节。通过记录只对精确匹配的关卡 revision 生效；当前版本未通过且存在更早版本的通过记录时显示“内容已更新，建议重做”。保留历史草稿与通过状态，内容回滚不删除较新版本记录。

当前内置课程的 courseId 为 `sql-quest-v1`，后续内容更新保持该身份。它与旧 `sql-quest` 的记录隔离，不自动继承旧草稿或通过状态。

## 4. 纯 JSON 契约

内容 JSON 不含函数、JS 表达式、HTML 模板、插件名或代码加载地址。模板、解法、典型错误、教学示例和拼图卡片可以包含 SQL 字符串，但只能经统一入口执行。夹具使用结构化数据，不接受 SQL 初始化脚本。

以下是独立的最小图书示例，使用 `example-course` 作为课程身份，说明根配置、关卡和夹具的关系。它不是现有源文件的完整正文，不能直接覆盖当前课程或已发布夹具。实际文件从 `content/course.json` 的登记路径读取，字段以正式 Schema 为准。

### 4.1 根配置

根配置示例，对应源文件位置 `content/course.json`：

```json
{
  "schemaVersion": 1,
  "id": "example-course",
  "revision": 1,
  "title": "SQL 入门",
  "objective": "通过小数据集学习只读查询。",
  "dialect": "sqlite",
  "themes": [
    {
      "id": "library",
      "title": "图书目录",
      "chapters": [
        {
          "id": "first-query",
          "title": "认识查询",
          "lessons": [
            {
              "id": "book-list",
              "title": "选择图书字段",
              "prerequisites": [],
              "path": "themes/library/first-query/book-list.json"
            }
          ]
        }
      ],
      "concepts": [
        {
          "id": "select",
          "title": "SELECT / FROM",
          "introducedAt": "book-list"
        }
      ]
    }
  ],
  "fixtures": [
    {
      "id": "library-basic-v1",
      "path": "themes/library/fixtures/library-basic-v1.json"
    },
    {
      "id": "library-empty-v1",
      "path": "themes/library/fixtures/library-empty-v1.json"
    }
  ]
}
```

规则：

- 根配置是允许列表，只有登记的关卡才会开放；文件存在不等于已经开放。
- `themes`、`chapters`、`lessons` 的数组顺序决定显示顺序，不按文件名或 ID 排序。
- `path: null` 表示未开放；非空地址缺失、损坏或身份不符必须报错，不当成未开放条目跳过。
- 主题 ID 在根中唯一，章节 / 关卡 / 知识点 ID 在主题内唯一；夹具 ID 在根中唯一。
- 关卡身份和先修声明必须与索引一致，先修指向本主题更早的关卡，禁止环和未知引用。
- 知识点 `introducedAt` 表示首次教授位置；关卡只使用本关或此前教授的概念。
- 所有引用地址相对于根 JSON 所在目录，允许嵌套 `.json` 路径，不依赖文件名等于 ID。这里展示源路径；浏览器读取的发布根必须添加第 5.4 节规定的版本前缀。

### 4.2 关卡

关卡示例，对应源文件位置 `content/themes/library/first-query/book-list.json`：

```json
{
  "schemaVersion": 1,
  "courseId": "example-course",
  "themeId": "library",
  "chapterId": "first-query",
  "id": "book-list",
  "revision": 1,
  "dialect": "sqlite",
  "mode": "guided",
  "title": "查看图书名称与价格",
  "prerequisites": [],
  "concepts": ["select"],
  "introducedConcepts": ["select"],
  "objective": "使用 SELECT 选择输出字段，用 FROM 指定表。",
  "statement": "从 books 表输出全部图书的 title、price，按这个顺序输出两列。保留重复记录，不要求行顺序。",
  "knowledge": [
    "表中的每行是一条记录，每列是一个字段。",
    "SELECT 指定输出字段，FROM 指定读取哪张表。",
    "选择字段不等于筛选记录；相同名称和价格可以来自不同记录。"
  ],
  "readableTables": ["books"],
  "previewFixtureId": "library-basic-v1",
  "duplicatePolicy": "preserve",
  "starterSql": "-- 在下方查询图书名称和价格。\n",
  "hints": [
    { "id": "idea", "text": "任务要全部图书，只需要选择输出字段。" },
    { "id": "syntax", "text": "使用 SELECT 字段列表 FROM 表名。" },
    { "id": "skeleton", "text": "SELECT title, price FROM ____;" }
  ],
  "referenceSolutions": [
    {
      "sql": "SELECT title, price FROM books;",
      "explanation": "按要求选出两列，保留全部记录及重复输出。"
    }
  ],
  "comparison": {
    "rowOrder": "unordered",
    "columnNames": "exact",
    "numbers": "exact"
  },
  "tests": [
    {
      "id": "basic",
      "fixtureId": "library-basic-v1",
      "expected": {
        "columns": ["title", "price"],
        "rows": [
          ["数据库入门", 39],
          ["SQL 手册", 59],
          ["SQL 手册", 59]
        ]
      }
    },
    {
      "id": "empty",
      "fixtureId": "library-empty-v1",
      "expected": { "columns": ["title", "price"], "rows": [] }
    }
  ],
  "expectedFailures": [
    {
      "id": "drops-duplicates",
      "sql": "SELECT DISTINCT title, price FROM books;"
    },
    {
      "id": "filters-records",
      "sql": "SELECT title, price FROM books WHERE price < 50;"
    }
  ]
}
```

关卡 `mode` 取 guided / practice / challenge。三层提示分别提供思路、语法和骨架；参考解法可有多条。`duplicatePolicy` 取 preserve / distinct，只用于说明输出要求，不能让比较器替学生去重。

`readableTables` 既决定数据区显示哪些表，也是学生查询的表允许列表。表结构、字段说明和预览数据直接来自预览夹具，不在关卡里再复制一份行数据。所有判题夹具必须提供兼容的可读表结构。

每个用例显式写完整列与行，预览夹具必须恰好对应一个用例。典型错误是出题审核数据：必须可执行，且至少一个用例的结果能识别其错误，不使用语法错误作为典型错误。

### 4.3 数据夹具

夹具示例，对应源文件位置 `content/themes/library/fixtures/library-basic-v1.json`：

```json
{
  "schemaVersion": 1,
  "id": "library-basic-v1",
  "tables": [
    {
      "name": "books",
      "description": "图书清单，每行代表一条独立记录。",
      "columns": [
        {
          "name": "id",
          "type": "INTEGER",
          "primaryKey": true,
          "description": "图书编号"
        },
        { "name": "title", "type": "TEXT", "description": "图书名称" },
        {
          "name": "price",
          "type": "INTEGER",
          "minimum": 0,
          "description": "价格，整数元"
        }
      ],
      "rows": [
        [1, "数据库入门", 39],
        [2, "SQL 手册", 59],
        [3, "SQL 手册", 59]
      ]
    }
  ]
}
```

空表用例 `library-empty-v1.json` 使用相同表结构，将 `id` 改为 `library-empty-v1`、`rows` 改为 `[]`。预览最多显示每表前 100 行，实际查询使用完整夹具。

夹具契约：

- 类型限定 INTEGER / REAL / TEXT。省略 `nullable` 表示不允许 NULL，校验器不会补入默认字段；主键不可为空，JSON null 表示 SQL NULL。
- 支持单列主键、外键、数值下界和普通索引。外键使用 `references: { "table": "categories", "column": "id" }`，只能指向同类型单列主键，记录必须有效。
- 可选根字段 `indexes` 使用 `{ "name": "books_price", "table": "books", "columns": [{ "name": "price", "direction": "ASC" }] }`；方向为 ASC / DESC，初始化器统一生成索引 SQL。
- `minimum` 只用于数值列，下界包含在内；INTEGER 值和下界必须是安全整数，REAL 必须有限。整值 REAL 也不能越过安全整数范围。
- 不允许任意 CHECK 表达式、触发器、视图、SQL 片段或脚本。编译器将字符串转义为 SQL 数据字面量，保留引号、空串、文本 NULL 和 NUL，不把数据当作 SQL 代码执行。
- 多表按声明建表，外键在全部数据装入后统一验证。夹具含额外表不代表学生获得读取权限。
- 数据使用固定 ID、固定日期和虚构人物；金额写明单位。不同记录可以有相同业务字段，不能误当重复数据删除。

### 4.4 教学流程图与 SQL 拼图

关卡可分别配置 `flowchart` 和 `sqlPuzzle`，两者都可省略。缺省时不显示入口，不用空配置占位，也不改变 guided / practice / challenge 的教学 mode。两者统一由正式 Schema、生成类型和校验器定义；未纳入契约的字段不能发布。扩展辅助能力需要更新前端，已有结构下新增内容只修改关卡 JSON。

| 字段                      | 内容与用途                                                                 |
| ------------------------- | -------------------------------------------------------------------------- |
| `flowchart`               | 包含 `exampleSql`、`nodes`、`edges`，解释一条固定、审核过的示例 SQL        |
| `flowchart.nodes[]`       | `id`、`label`、`description`，均为纯文本；ID 在该图内唯一                  |
| `flowchart.edges[]`       | `from`、`to` 引用节点 ID，可选纯文本 `label` 说明连接                      |
| `sqlPuzzle.cards[]`       | `id`、`sql`，ID 在该拼图内唯一，卡片直接显示其实际 SQL 片段                |
| `sqlPuzzle.solutionOrder` | 一种参考拼法的卡片 ID 序列，仅用于作者核对及用户主动查看参考，不是判题规则 |

- 流程图使用预览夹具和本关 `readableTables`，不再复制表结构、预览行或伪造中间结果。节点 1 至 20 个、连线至多 32 条，禁止未知引用、重复连线、自环和有向环。节点 / 连线只描述教学关系，不驱动查询执行；不提供 HTML、SVG、Mermaid 源码、脚本、外链资源或自定义样式的渲染入口。文字长度在正式 Schema 中限量。
- 拼图包含 2 至 40 张非空卡片，每张 SQL 片段至多 1,000 字符；`cards` 数组仅决定候选区顺序，首次拼接区为空。每张卡片一次最多使用一次，相同 SQL 文本可用不同 ID 的卡片提供。参考序列非空、无重复 ID、引用全部存在，可以不使用干扰卡；不得直接作为学生初始排列。
- 卡片按词法边界拆分，不把字符串字面量、带引号标识符、多字符运算符或注释拆到多张卡片。共享纯函数按所选顺序用一个 ASCII 空格连接卡片的原始 sql，不调整子句顺序、不补写缺失条件或偷偷删卡；整句仍遵守 20,000 字符预算，不因来自拼图而放宽 SQL 限制。
- 内容审核需验证示例 SQL 在预览夹具上只读且可执行，图示含义与示例相符；参考拼法生成的 SQL 必须通过该关全部用例。所有配置仍受关卡正文大小限制，格式 / 引用错误按内容加载错误处理，不能静默丢弃辅助内容。改变示例语义、卡片内容或参考拼法时递增关卡 revision。

## 5. API 与内容发布

### 5.1 统一读取方式

部署参数 `VITE_CONTENT_ROOT_URL` 指定根地址，默认 `./content/course.json`，相对于应用部署基路径解析。应用部署到 `/sql-quest/` 时，默认入口为 `/sql-quest/content/course.json`。

接口只需三类 GET，正文直接返回 JSON，不包 `{ code, data }`，不使用 JSONP，也不要求物理文件与路由同名。

| 对象   | 静态资源示例                                                                   | API 示例                                                                   |
| ------ | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 根配置 | `/sql-quest/content/course.json`                                               | `/api/sql-quest/course.json`                                               |
| 关卡   | `/sql-quest/content/releases/r1/themes/library/first-query/book-list.json`     | `/api/sql-quest/releases/r1/themes/library/first-query/book-list.json`     |
| 夹具   | `/sql-quest/content/releases/r1/themes/library/fixtures/library-basic-v1.json` | `/api/sql-quest/releases/r1/themes/library/fixtures/library-basic-v1.json` |

静态模式与 API 模式共用 Fetch、Schema、加载状态和判题流程，不保留另一条构建时导入课程的生产路径。新增内容只发布 JSON 并更新根；改变根入口部署参数或引擎 / Schema 能力才需要发布前端。

### 5.2 路径与网络规则

- 根入口限同源，生产使用 HTTPS，本地开发允许 HTTP；根 URL 不含凭据、查询参数或片段。外部内容服务通过同源反向代理接入，不使用登录、跨域 Cookie 或任意跨域源。
- `path` 使用小写 ASCII 字母、数字、下划线、连字符及 `/` 分层，以 `.json` 结尾。拒绝协议、绝对路径、`.` / `..` 目录段、反斜杠、百分号编码、查询参数和片段。
- 先校验路径文本，再用 URL API 解析并检查 origin、内容目录边界、重复地址和根自身引用。禁止重定向，防止合法地址转向其他来源。
- 只请求根中显式登记的资源。请求用 GET、JSON Accept、`credentials: omit`，不附带学习数据或 Cookie。
- 响应要求 HTTP 200 与 JSON 媒体类型；404、服务错误、错 MIME、坏 JSON、未知 Schema 和引用不一致均报告为内容错误，不展示成空题。
- 每请求含正文读取限 10 秒，完整加载限 60 秒，并发最多 4 个。根 / 关卡各限 1 MiB，单夹具限 2 MiB，总正文限 32 MiB，按解压后的实际字节计数；不只相信 Content-Length，不对无界响应直接调用 response.json()。

### 5.3 加载生命周期

加载顺序为根配置、已登记的开放关卡与全部夹具、校验、启用练习。必须整套通过后一次启用；不做局部注册、目录分页、按关缓存或后台轮询。

每次加载有独立标记和 AbortController；失败取消剩余请求，销毁或重试使旧标记失效。只有完整内容快照可运行判题，迟到响应不能替换新快照。

错误页说明失败阶段并提供重试、本地记录导出；不无限重试、不静默切换到其他课程、不清除 IndexedDB。错误文本不直接渲染服务端返回的 HTML。

### 5.4 发布与更新

源码使用第 4 节中的相对路径。发布时将引用文档放入 `releases/r<根 revision>/`，发布根为每个非空 path 添加相同版本前缀，正文身份保持不变。客户端确认所有资源属于该根对应的发布目录。

先上传并核对版本资源，最后原子更新根。版本地址发布后不可变，新内容用递增 revision；共享夹具变更同时创建新夹具 ID。不要原地覆盖旧关卡正文，使已缓存文件与新根混用。

根使用重验证缓存，例如 `Cache-Control: no-cache` 配合 ETag；版本资源可长期 immutable 缓存。客户端一页会话固定一份完整快照，新版在重新打开或刷新后生效，不热替换正在执行的内容。回滚切回完整旧根及旧发布资源，不能拼接版本。

不提供持久内容缓存或 Service Worker。课程和引擎资源加载后，练习不再请求内容 API；不能保证首次离线打开可用。发布服务必须保持版本资源不可变，版本路径本身不提供签名或考试防作弊能力。

## 6. SQL 执行与判题

### 执行请求

`prepare` 请求包括 schemaVersion、requestId、contentToken、rootRevision、courseId、themeId、lessonId、lessonRevision、mode、inputMode、SQL、关卡文档和该模式所需的 JSON 夹具。执行 mode 为 run / submit，inputMode 为 text / puzzle，均与关卡的 guided / practice / challenge 教学 mode 不同。协议 run 只执行预览用例，submit 执行全部用例；界面仅提供“运行”按钮，统一调用 submit。run 是内部预览能力，没有独立按钮；请求不发送课程全集或内容 URL。执行客户端另行捕获第 7 节定义的 recordGeneration，用于接收结果和保存时的校验，不把记录元数据传给 Worker。

主线程从已校验课程构造不可变快照，并同步校验请求。每次有效执行请求创建一个新的模块 Worker，不复用上次请求的 Worker。Worker 再校验消息、身份、可读表和所需夹具关系，完成引擎加载后返回 `ready`，此时不执行用例，也不自行 fetch 内容或读取内置课程。15 秒准备期限从创建 Worker 前开始，到收到有效 ready 为止，包含 Worker 启动、引擎加载和 Worker 请求校验；此前主线程的请求构造与同步校验不在该计时段内。

主线程收到 ready 后，按关卡 tests 顺序逐个发送 `run-case`，协议 run 模式仅派发预览用例。每条消息携带原请求身份、caseId 和从 0 开始的 caseIndex；caseIndex 是该用例在完整 tests 数组中的位置，预览用例不一定为 0。Worker 只执行已准备快照中对应且尚未执行的用例，通过共享编译器重新建库，返回 `case-result` 后不自动进入下一用例。主线程仅在当前用例通过后派发下一用例；任一错误、结果不符、取消或超时结束请求，正常完成后也会终止 Worker。只有 submit 全部用例通过才允许写入通过记录。

ready、case-result 与错误响应回传相同请求与内容身份；用例响应还必须匹配当前 caseId 和 caseIndex。主线程检查 Worker 实例、requestId、完整快照身份、客户端捕获的记录代次及协议顺序；旧请求、已处理阶段的重复或迟到消息直接忽略，不能推进状态、清除当前定时器或写入记录。当前阶段的非法消息按协议错误结束该请求，不静默等待。切关、切主题、取消、销毁，以及确认导入替换或清除都会使旧执行失效。消息定义统一进入正式 Schema，不另建 Worker 专用契约。

### SQL 限制

只允许单条只读查询，使用 SQLite 准备接口完整处理语句尾部，并结合授权机制限制可读表与纯计算函数。不能用 SELECT 前缀、分号拆分或单独 query_only 判断安全。

拒绝写入、DDL、ATTACH / DETACH、用户 PRAGMA、事务、扩展加载、文件和宿主函数，也不接受 EXPLAIN、未绑定参数或虚表。可用计算函数由引擎的显式允许列表决定，不是所有只读 SQLite 功能都开放。夹具初始化权限不开放给学生，Worker 是执行隔离与取消机制，不是任意代码沙盒。

每次执行的每个用例重建内存数据库。主线程在发送每条 run-case 前启动独立的 3 秒期限，以单调时钟计时，覆盖消息传递、建库与装载、SQL 准备与执行、完整结果读取、判题时的比较及数据库清理，到接收有效 case-result 为止；不包含之前的引擎加载或后续 IndexedDB 保存。接收响应时也检查期限，不能因定时器回调延迟而接受超时结果。每个用例重新计时，不能给整次运行判题共用 3 秒，也不能用“用例数 × 3 秒”替代逐用例限制。

主线程负责超时终止 Worker、清理定时器并使本次请求失效，下次执行重建；不能依赖被同步 SQL 阻塞的 Worker 自行处理取消。Worker 仅在主线程派发后执行用例，任一用例超时都不能记录部分通过。

资源预算：SQL 至多 20,000 字符、每用例 3 秒、引擎加载与请求准备共 15 秒、单夹具 5,000 行且生成 SQL 不超过 1 MiB、完整结果 1,000 行 / 100 列、展示 100 行、SQLite 单值 / 行长度 1 MiB、单用例文本结果合计 4 MiB。超限明确失败，不截断后判通过；预算不能保证任意查询都不会耗尽内存。

### 比较规则

| 对象     | 规则                                                                       |
| -------- | -------------------------------------------------------------------------- |
| 列       | 数量、顺序与题目要求的列名 / 别名精确匹配                                  |
| 无序行   | 多重集一一匹配，保留重复次数                                               |
| 有序行   | 逐行匹配，题目必须明确可观察的次排序键                                     |
| NULL     | 两侧 NULL 单元格可匹配，不等于空串、0 或文本 NULL；不是 SQL 的 NULL = NULL |
| 文本     | 不自动 trim、变大小写或转数字                                              |
| 整数     | int64 范围检查后再转 Number，超出安全范围明确报错                          |
| 浮点     | 默认精确，只在指定列启用容差；无序行仍一一匹配                             |
| 空结果   | 合法，仍比较列元数据                                                       |
| 不支持值 | 非有限数值、BLOB 等明确报错，不静默转换                                    |

容差采用 `abs(actual - expected) <= max(absTolerance, relTolerance * abs(expected))`。需要时 comparison 使用 `numbers: tolerant`，并在 `tolerances` 中按从 0 开始的 column 声明 absTolerance / relTolerance；不给整行、计数或金额自动加容差。

点击“运行”检查全部用例，全部通过后自动记录对应关卡 revision，无需再次提交；仅预览数据正确不能通关。全部通过时显示预览用例的实际查询结果，结果不符时显示失败用例的实际与参考结果；不额外执行第二次查询，也不用参考结果冒充实际输出。内部 run 预览模式不记录通关。比较结果而非 SQL 字符串，允许受支持的等价只读解法。多用例识别常见错误，不证明学习者理解，也不能防前端作弊。

### 界面

任务展示必要知识、输出列、边界、重复和排序要求。数据表区分 SQL NULL、空字符串和文本 NULL，保留完整字段含义。表格仅在容器内横向滚动，不让页面横向溢出。

同时执行一个请求，编辑器可继续修改；结果标明对应运行快照。加载、执行、取消、超时、语法错误、结果不符、空结果、通过、超限和保存失败都有明确文字状态。

查看答案不修改草稿；填入答案需确认，取消保持原 SQL。“恢复默认”直接将当前文本 SQL 重置为本关起始模板，无确认弹窗，可撤销，不自动执行、不清除通过记录、拼图草稿或其他关卡记录。提示按思路、语法、骨架逐层展开，不扣分；复习由用户标记，不把提示使用情况当成独立掌握的证据。

视觉规范见 [AGENTS.md](../AGENTS.md)，内容 JSON 不控制组件、CSS 或远程字体。动态增加中文内容必须能使用字体回退，不因缺字要求重建应用。

流程图放在题目区，SQL 区提供“文本 / 拼图”输入方式切换；手机沿用题目 / 数据 / SQL / 结果入口，不增加第四个桌面主栏。仅配置对应辅助内容的关卡显示入口，查看流程图不改变 SQL、草稿或通过状态。

### SQL 编辑与补全

编辑器复用 CodeMirror 6 的 SQLite 语言与补全扩展，提供关键字、可读表名和字段候选。候选在本地生成，不发送学生 SQL、不执行查询、不请求 API，也不从答案、典型错误、判题结果或数据行提取建议。不维护逐关词表或第二份字段定义，不引入语言服务器或完整 SQL 解析器。查询权限仍由 Worker 校验。

- 关键字候选来自 SQLite 只读查询语法，如 SELECT、FROM、WHERE、JOIN、GROUP BY、ORDER BY；不推荐写入、DDL、PRAGMA 等被引擎禁止的语句。输入匹配不区分大小写，接受时插入大写关键字，不自动改写已有 SQL 的大小写。
- 表名与字段候选只来自当前已校验快照中 `readableTables` 对应的预览夹具结构，沿用字段名、类型和说明，不能包含夹具的额外表或其他关卡的表。候选区分关键字、表和字段，字段注明所属表及类型，说明按纯文本展示；插入时保留实际名称，必要时按 SQLite 标识符规则加引号。
- 支持单表、常规 JOIN，以及有 / 无 AS 的表别名补全。使用当前语句的语法上下文解析 FROM / JOIN，包括光标后已经写出的表引用；例如 `SELECT b.t FROM books AS b;` 中编辑 `b.t` 时能补为 `b.title`。输入 `表名.` 或 `别名.` 时只列出对应可读表的字段；未限定字段优先使用已确定的查询范围，同名字段显示并插入可消歧的表名 / 别名前缀，不随意选一张表。
- SQL 尚不完整、无法确定查询范围时，可提供标明来源的当前可读表与字段，不声称这些名称已在查询中绑定；无法识别限定符时不猜测其字段。不完整推断子查询 / CTE 的派生字段，不能把内部别名误当作外层已绑定的表；无法可靠判断时减少候选，不阻止继续输入。
- 输入关键字 / 标识符前缀或限定符后的点号时可自动弹出候选；提供 Ctrl+Space 和可点击的“补全”按钮，手机与快捷键被输入法占用时仍可使用。在字符串字面量、注释和中文输入法组合输入期间不弹出候选、不拦截输入法按键；组合输入开始时关闭已有候选，结束后按当前文档重新判断，不自动接受候选。
- 候选菜单激活时用上下方向键选择、Enter 接受已选候选、Escape 关闭；Tab / Shift+Tab 保持焦点导航，不默认用于接受补全或困住焦点。支持触屏选择，菜单不被软键盘或面板裁剪，接受后焦点回到编辑器。一次接受只替换补全范围、保留已有限定符，光标在标识符中间时不重复已有后缀，作为一次可撤销编辑；不替换整句、不自动运行判题。
- 候选始终与当前编辑器文档和关卡快照一致。切题、切主题、替换编辑器内容或销毁编辑器时关闭旧菜单并更新补全上下文，旧候选不能应用到新文档；普通输入变化也需重新核对替换范围。新增合法关卡和夹具后自动获得对应表 / 字段补全，不要求修改前端或内容契约。

### 卡片 / 拼图式 SQL 组合

- 采用“卡片池 + 有序拼接区 + 只读 SQL 预览”，支持选择、移除和重排卡片，不建设任意嵌套积木语言。预览始终显示共享拼接函数实际产生的完整 SQL；尚未拼好时允许继续调整，不按参考序列自动纠错或把拼图形状当作查询正确性的证明。
- 桌面可拖拽，手机与键盘必须能通过“添加、前移、后移、移除”按钮完成同样操作，不能只有拖拽入口。操作后保留合理焦点并说明移动结果，提供撤销；清空拼图或填入参考拼法先确认，取消保留当前排列。
- 文本与拼图保存独立草稿，切换输入方式时关闭补全菜单和未完成拖拽，不覆盖另一份内容，也不自动把任意手写 SQL 反向解析成卡片。“填入编辑器”先展示生成 SQL，替换已有 SQL 时确认，接受后作为一次可撤销编辑；取消不改变两份草稿。参考拼法仅在用户主动查看答案时展示，查看与填入分开。
- 运行判题取当前输入方式的 SQL，并在主线程冻结 SQL、关卡快照和来源标记；拼图直接生成 SQL，不要求先覆盖文本草稿。卡片引用无效、重复使用或超出 SQL 预算时明确报错，不执行截断或自动修复后的内容；其他语法错误由同一执行入口反馈。
- 文本与拼图共用 Worker、可读表权限、逐用例时限和完整结果比较，不给拼图另建比较器，也不按 solutionOrder 或卡片顺序判通过。结果注明对应的 SQL 与输入方式，运行中继续改卡片或切换输入方式不改变在途快照；全部用例通过才记录关卡通过，不把拼图通过描述为独立手写 SQL 的掌握证明。
- 拼图草稿按相同课程 / 主题 / 关卡及 revision 隔离。切题、切主题、内容更新或确认导入 / 清除时取消未完成拖拽、清理旧预览与操作上下文；旧事件不能改变新关卡或新记录代次的卡片排列。

### 学习记录

IndexedDB 以稳定关卡身份分组，按关卡 revision 分槽保存文本草稿、拼图草稿、输入方式、通过状态、已查看提示与复习标记。不长期保存全部查询结果，不持久化练习数据库。

拼图草稿 `puzzleDraft` 保存 `cardOrder` 及同次拼接的 `sql` 文本快照，输入方式 `inputMode` 为 text / puzzle；这些定义与学习记录、备份一起纳入正式 Schema，不复用关卡教学 mode 或执行请求的 run / submit。正常恢复时按同 revision 的卡片配置核对序列与 SQL 一致性，再生成预览。没有同 revision 的拼图配置时使用文本入口；配置缺失、卡片引用未知或快照不一致时保留原记录及 SQL 供查看 / 导出，不自动套用新版卡片、删卡、覆盖文本草稿或执行历史快照。流程图当前选中节点与拖拽中间状态不持久化。

- 普通保存和判题只更新请求所属 revision 的槽及本次变更的字段，不用旧页面的整条记录覆盖其他版本或已通过状态；同一 revision 的通过状态只能由未通过变为通过，显式导入替换或清除除外。
- 当前 revision 已有记录时恢复该槽；没有时从本关起始模板开始。其他 revision 的草稿按版本降序单独展示，复制前确认，不自动填入当前版本。后续编辑只保存到当前 revision，保留原版本草稿。
- 提示和复习状态只读写当前 revision，不把旧版本提示 ID 套到新版。新旧页面、内容回滚和重复练习都不能删除另一 revision 的状态；例如先通过 revision 2 再通过 revision 1，两个通过状态均保留。

文本编辑和已完成的拼图操作短时防抖保存并显示状态；卡片序列与对应 SQL 快照同次更新，不把两次排列混存。保存失败时保留本页多关的两类草稿，随现有备份一并导出和原子恢复，不因切关或网络失败丢弃未保存内容。两类草稿均遵守下述记录代次和事务冲突规则。

记录元数据包含记录集版本和 `recordGeneration`：前者每次成功写入递增，后者只在成功整体替换或清除时递增，两者都不是内容 revision。所有防抖保存、异步回调和判题请求在创建时捕获不可变的记录代次，写入事务同时核对代次与记录集版本，不能在回调执行时把旧任务重新绑定到当前代次。

无法读取记录元数据时暂停持久化，仍允许本页练习并保留草稿供导出，不伪造已保存状态或默认代次。存储恢复后先读取已有记录、处理冲突，再由用户确认保存本页修改，不自动重放旧写入。

多标签页写入冲突时暂停覆盖并保留本页修改，让用户选择读取已存版本或合并本页未保存的版本槽；同槽同字段冲突须明确选择，不能静默最后写入获胜。合并也遵守通过状态不回退和 revision 隔离规则。发现记录代次改变时，旧队列和旧判题一律失效；本页未保存草稿只保留供查看、导出或用户重新确认合并，不自动写回。广播只用于及时提示，不代替事务检查。

### 备份、导入与清除

正常导出的完整备份必须能通过本应用的格式与大小校验并完整恢复，包括历史版本、未知课程、不在当前目录中的记录，以及本页未保存的合法草稿；若同一版本槽存在未解决冲突，先让用户选择，不静默丢弃任一侧。导出固定一份一致记录快照，不能在生成不同文件时混入后续编辑。

- 备份采用分卷 JSON，每卷按最终 UTF-8 正文计不超过 5 MiB；小备份也是一卷。每卷含格式版本、导出时间、backupId、从 1 开始的 partIndex、partCount 和 records，共同元数据一致。按关卡身份与 revision 将记录分配到卷中，同一版本槽只出现一次。字段长度与条数由正式 Schema 限定，存储与备份共用约束，保证每条合法记录连同卷头能放入一卷；不截断草稿、不遗漏历史记录。
- 5 MiB 是单卷输入上限，不是整个记录集的上限。导入一次选择完整的一组文件；先检查文件大小与总量，向用户说明完整替换的范围，逐卷限量解析、Schema 校验和去重，核对 backupId、卷数、连续序号及共同元数据。缺卷、重复卷、混组或坏记录均拒绝整组，不按文件名判断完整性，不逐卷覆盖正式数据。
- 每次导入使用隔离的临时区，逐卷校验到临时存储，不把整组拼成一个无界内存对象。全部校验完成并预览后，才允许用户确认整体替换；临时区与正式区隔离，取消、失败或中断后的临时数据可清理，不自动启用。容量不足或存储不可用时明确失败并保留正式数据，不能退化为部分恢复。临时导入不改变正式记录集版本。

导入替换与清除共用同一保护流程：

1. 确认前不取消现有练习或改写记录。预览说明会替换正式记录与本页草稿，提供先导出的入口；取消确认保持原状。
2. 确认后暂停学习交互和普通保存，取消防抖队列、使旧请求失效并终止在途 Worker，清理结果与定时器。已经发起的保存事务须结束或中止后才能开始替换；保留本页草稿缓冲，尚不清空。
3. 在同一 IndexedDB 事务内重新核对预览时的记录集版本与代次，从已校验临时区复制全部记录或清空正式记录，并递增记录集版本和 recordGeneration。预览后发生其他写入则中止并要求重新预览，不覆盖新数据。元数据不随清除删除，也不从备份恢复旧值。
4. 仅事务成功后更新本页代次、同步内存记录与编辑器并清理旧草稿缓冲，恢复交互。失败也恢复交互，保留正式记录与本页草稿，显示重试 / 导出入口，但不自动重放已取消的队列或旧执行。其他页面即使错过通知，其旧写入也会因事务内代次检查而失败。

备份中的 SQL 和路径只作为数据，不执行。导入完成后清理本次临时区；应用站点与课程身份的关系不因备份文件名或内容 API 地址改变。

记录按应用站点来源保存，API 地址不参与记录键。应用域名、协议或端口改变时需手动备份迁移；浏览器可能回收数据，不能承诺永久保存或关页前最后一次编辑必然落盘。

## 8. 教学路线

当前内置图书 23 关、商品 24 关、校园选课 13 关，各有六章，共 60 关。各主题独立安排，关卡数量和开放情况以根配置为准。

下表是商品主题的教学顺序，不是全部课程清单，也不决定首屏主题。

| 章  | ID      | 任务         | 教授内容                       |
| --- | ------- | ------------ | ------------------------------ |
| 1   | sql-l01 | 查看数据     | 表、行、列，SELECT / FROM      |
| 1   | sql-l02 | 选择字段     | 选列与筛行的区别               |
| 1   | sql-l03 | 列别名       | AS 与输出名称                  |
| 2   | sql-l04 | 比较条件     | WHERE 与比较运算               |
| 2   | sql-l05 | 组合条件     | AND / OR、括号和优先级         |
| 2   | sql-l06 | 多个可选值   | IN                             |
| 2   | sql-l07 | 文本匹配     | LIKE                           |
| 2   | sql-l08 | 空值判断     | NULL、IS NULL / IS NOT NULL    |
| 3   | sql-l09 | 排序结果     | ORDER BY、次排序键             |
| 3   | sql-l10 | 限制条数     | 排序后 LIMIT                   |
| 3   | sql-l11 | 去除重复     | DISTINCT 对输出列组合去重      |
| 4   | sql-l12 | 统计记录     | COUNT(*) 与 COUNT(column)      |
| 4   | sql-l13 | 数值聚合     | 单行表达式、SUM / AVG          |
| 4   | sql-l14 | 分组统计     | GROUP BY、结果粒度             |
| 4   | sql-l15 | 筛选分组     | HAVING 与 WHERE                |
| 4   | sql-l16 | 分类统计报告 | 筛选、分组、聚合和排序         |
| 5   | sql-l17 | 认识关联键   | 表关系，不要求 JOIN            |
| 5   | sql-l18 | 内连接       | INNER JOIN、表别名、同名列消歧 |
| 5   | sql-l19 | 一对多连接   | 行数变化与链式连接             |
| 5   | sql-l20 | 左连接       | LEFT JOIN、未匹配 NULL         |
| 5   | sql-l21 | 连接与筛选   | ON / WHERE 的差异              |
| 6   | sql-l22 | 关联汇总     | 关联、表达式聚合、分组         |
| 6   | sql-l23 | 未匹配项     | 左连接、右表键计数、零匹配     |
| 6   | sql-l24 | 综合查询     | 汇总、确定性排序、Top N        |

普通关集中一个新概念，配套语法当关解释；综合关只组合已学内容。商品基础路线不要求 DDL、写入、事务、子查询、窗口函数或索引优化。

关键教学口径：

- LIKE 明确 `%`、`_` 与所用大小写规则；NULL、空串和文本 NULL 不混同。
- 没有 ORDER BY 不保证顺序；LIMIT 必须先说明排序和并列边界，DISTINCT 不代表排序。
- 空输入且无 GROUP BY 时 COUNT 为 0、SUM / AVG 为 NULL；有分组时空输入零行。AVG 忽略 NULL，但不忽略零，不自动按数量加权。
- 非聚合输出字段列入 GROUP BY，不依赖 SQLite 裸列扩展；多条明细展开不是天然错误重复。
- LEFT JOIN 同时考虑无关联行和只有不符合筛选条件的关联行，ON 条件移到 WHERE 不必然等价。
- 交易金额使用历史明细成交价，分组使用稳定身份，不合并同名顾客；零匹配、并列和 Top N 是否扩容都写进题意。

流程图和拼图按第 4.4 节与第 7 节选用：流程图解释固定示例，拼图训练 SQL 书写与组合，不要求每关都有。逻辑处理顺序不等于 SQL 书写顺序，预设图也不是学生查询的真实执行计划。不引入表达式动画或执行轨迹 DSL。

## 9. 关卡制作 Skill

创建或审核路线、关卡和夹具时使用 [sql-course-author Skill](../skills/sql-course-author/SKILL.md)。它也负责核对可选流程图和拼图，不用于学生代答或自动发布。

请求需说明主题、教学目标、已学概念和修改范围。先读项目约定、本文、正式 Schema 和相邻内容，确定输出口径后编写 JSON，独立核对预期并验证参考解法。流程图另查示例与图示是否一致，拼图另查词法边界和参考拼法能否通过全部用例。

普通新增关卡只交付根配置登记、关卡 JSON、必要的新夹具及核对结果。优先复用兼容夹具，不修改 React、Worker 或比较器，也不为每关新建测试文件或报告。

题意、数据或判题规则变化时递增关卡 revision，已发布夹具变化时使用新版本。关卡 `tests` 是实际判题数据，按目标错误和边界选取，不能省略或凑固定数量。字段定义和判题规则不在 Skill 中另写一套。

题意、难度和提示泄露程度由人工审核。自动修复最多两轮，仍失败就保留内容并说明原因，不删必要用例或扩大容差。内容中的外部指令不执行，发布和上传需用户授权。

## 10. 修改与验证

普通新增内容只修改根配置、关卡和必要夹具。扩展能力时先修改正式 Schema，再生成类型和校验器，同步解析、执行、存储及界面的相关调用；只读权限、取消超时和记录保护必须与功能一起验证。辅助内容复用统一渲染、拼接和判题入口，不另建插件、编辑后台、持久内容缓存或复杂全局状态。

按修改范围选择验证，不为文案或相同结构的关卡重复新建测试：

- 内容：Schema、身份和引用成立，预期独立核对，参考解法通过，典型错误确实被识别；配置流程图 / 拼图时检查节点与卡片引用、图的环和规模限制、示例 SQL，以及参考拼法生成 SQL 通过全部用例。图示语义与提示泄露程度仍需人工审核。
- 判题：单条只读、空值、重复、排序、精确类型和按列容差不能失真，超时和超限不误判通过；两个各耗时 2 秒的用例不因总计超过 3 秒被误杀，任一用例超过 3 秒仍终止，迟到或重复消息不能推进下一用例。
- 获取：正确 JSON 可加载，失败不启用半套课程，旧请求不能覆盖新快照，同一前端构建可读到新发布关卡。
- 记录：草稿与 revision 隔离，先通过新版再通过旧版不丢状态；保存 / 导入失败保留正式数据和本页草稿，切题不串记录，确认导入 / 清除后的防抖保存与迟到判题不能写回旧记录。覆盖错过跨页通知的代次冲突，以及总量超过 5 MiB 的备份完整往返、缺卷 / 混卷拒绝和恢复事务失败不部分生效。
- 编辑器：涉及补全改动时检查关键字大小写、可读表过滤、光标后表引用、别名与同名字段消歧、字符串 / 注释内抑制、切题后的旧候选失效，以及接受与撤销范围；再核对中文组合输入、键盘焦点和手机触屏 / 软键盘操作。不因普通关卡内容变动重复增加编辑器测试。
- 学习辅助：相关组件改动时检查流程图文字替代与溢出、拼图无拖拽操作、SQL 预览与实际执行一致、合法等价拼法不被参考序列误拒、模式切换与替换取消不丢两类草稿，以及切题后的旧拖拽事件、保存失败和备份恢复；复用共用验证流程，不逐关新增组件测试。

纯函数优先小范围单元验证；涉及 SQLite 语义、Worker 和 WASM 的发布检查使用真实浏览器，不以 mock 代替。UI 变更再检查桌面 / 手机、键盘、焦点、字体与溢出；不为纯内容编辑无差别新增全套截图或 E2E 文件。

检查命令必须对应 package.json 中的实际脚本，只报告已执行的结果。没有相关需求，不扩展测试体系、持续集成或报告系统。
